# 알려진 한계 및 제한사항

이 문서는 프로젝트의 현재 한계와 향후 개선이 필요한 부분을 정리합니다.

## 전체 프로젝트

### 기술적 한계

- **데이터 저장**: 모든 앱이 브라우저 `localStorage`만 사용하여 데이터가 브라우저/기기별로 분리됨
- **동기화 없음**: 여러 기기 간 데이터 동기화 불가
- **백업 제한**: 사용자가 직접 JSON 파일로 내보내기/가져오기 필요
- **오프라인 지원**: 외부 API(날씨, 뉴스)는 네트워크 필요

### 배포

- **정적 파일만**: 서버 없이 정적 파일로만 구성되어 GitHub Pages 등에서 호스팅 가능
- **HTTPS 권장**: 일부 브라우저 기능(알림 등)은 HTTPS 필요

---

## home/ (시작 페이지)

### 한계

- 날씨는 서울 고정 (위치 변경 불가)
- 뉴스는 Hacker News(영어) 고정, 한국어 뉴스 미지원
- 할 일 목록은 간단한 기능만 (카테고리, 날짜 없음)

### 외부 API 의존

- **Open-Meteo**: 무료 API, 가끔 응답 지연 발생 가능
- **Hacker News**: Algolia API 사용, 서비스 장애 시 뉴스 표시 불가

---

## quiz/ (상식 퀴즈)

### 콘텐츠 한계

- 32문항 고정 (한국사, 과학, 지리, 예술과 문화 각 8문항)
- 문항 추가 시 수동으로 `questions.js` 편집 필요
- 한국어 문항만 지원

### 기능 한계

- 순위는 상위 8명까지만 저장
- 사용자 인증 없음 (누구나 아무 이름으로 순위 등록 가능)
- 문항 난이도 조절 로직 없음 (무작위 출제)

### 검증 규칙

- 최상급 표현('가장', '최초' 등)이 있는 문항은 `criteria` 필드에 기준 명시 필요
- 논쟁 가능한 사실(예: 나일강 vs 아마존강 최장)은 해설에 양측 주장 기재

## todolist/ (할 일 관리)

### 한계

- 반복 일정 미지원
- 알림/리마인더 기능 없음
- 하위 작업(subtask) 미지원
- 태그 기능 없음 (카테고리만 지원)

### 자동 분류

- 키워드 기반 단순 매칭 (AI 분류 아님)
- 동음이의어 구분 불가
- 사용자가 키워드 직접 관리 필요

---

## handwrite/ (손글씨 인식)

### 모델 한계

- **숫자만 인식**: 0-9 숫자 한 글자만 인식
- **한글/영문 불가**: MNIST 데이터셋 기반이라 숫자 외 문자 미지원
- **필기 스타일**: 훈련 데이터와 다른 필기체는 정확도 저하

### 기술적 한계

- 모델 크기: 약 400KB (로컬 저장)
- 추론 속도: 대부분 기기에서 100ms 이내
- GPU 가속: TensorFlow.js WebGL 백엔드 사용 시 더 빠름

### 출처

- 이 앱은 외부 오픈소스 템플릿(InkNet)을 기반으로 함
- 라이선스: MIT
- 원본 저작권: InkNet contributors

---

## portfolio/ (마케팅 포트폴리오)

### 주의사항

- **가상 인물**: 이하린은 실습용 가상 인물
- **예시 데이터**: 모든 수치와 사례는 실제가 아닌 예시
- **연락처 비활성**: 이메일 링크는 연결되지 않음

---

## laundry/ (세탁실 프로토타입)

### 한계

- **시뮬레이션 전용**: 실제 세탁기와 연동되지 않음
- **1인 화면**: 여러 사용자의 동시 접근 시나리오 미구현
- **IoT 미연동**: 실제 센서/장비 연결 없음

### 범위 외

- 관리자 화면
- 고장 신고
- 결제 기능
- 다국어 지원

---

## 향후 개선 가능 사항

1. **서버 추가**: Node.js/Firebase 등으로 데이터 동기화
2. **PWA 전환**: 오프라인 지원, 홈 화면 추가
3. **퀴즈 확장**: 문항 추가, 사용자 기여 문항
4. **손글씨 확장**: 한글/영문 인식 모델 추가
5. **다국어 지원**: 영어 UI 추가
