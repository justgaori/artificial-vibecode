# 개발 과정에서 사용한 프롬프트

이 기록은 이번 구현에서 실제로 받은 지시와, 그 지시를 수행하면서 기획서에 맞추다 고친 순서를 적습니다. 입력하지 않은 문장을 사용자 프롬프트인 것처럼 추가하지 않았습니다.

사용한 환경은 Cursor입니다. 과제 안내문은 Claude Code를 전제로 하지만, 아래 1번의 지시는 Cursor 대화에 입력된 내용입니다.

## 1. 최초 프롬프트

> 휴먼 컴퓨터의 문서 목록을 보고
>
> [중요과제] Claude Code를 활용한 기획 결과물 구현 및 공유
> 1. 과제 목적
> 지금까지 기획한 프로젝트 내용을 바탕으로 Claude Code를 활용하여 실제 웹사이트 또는 서비스를 구현하고, 완성된 결과물과 개발 과정에서 사용한 프롬프트를 함께 제출한다.
>
> 2. 과제 수행 내용
> 지금까지 기획한 프로젝트의 목적, 주요 기능 및 사용자 요구사항을 정리한다.
>
> Claude Code를 활용하여 기획 내용을 실제 웹사이트 또는 서비스로 구현한다.
>
> 구현 결과를 실행하고, 오류를 수정하거나 추가 프롬프트를 입력하여 기능과 디자인을 개선한다.
>
> 완성된 프로젝트를 웹에 배포하거나 다른 사람이 실행 및 확인할 수 있도록 공유한다.
>
> 개발 과정에서 사용한 프롬프트를 정리한다. 최초 프롬프트뿐 아니라 기능 추가, 오류 수정 및 디자인 개선에 사용한 프롬프트도 포함한다.
>
> 3. 제출물
> 구현한 프로젝트의 소스 코드 또는 GitHub 저장소 링크
>
> 실행 가능한 결과물 또는 배포된 웹사이트 링크
>
> 개발 과정에서 사용한 프롬프트 전체 내용
>
> 프로젝트 설명 및 주요 기능 요약
>
> 4. 평가 기준
> 기획 내용과 구현 결과의 일치성
>
> 주요 기능의 구현 및 정상 작동 여부
>
> 사용자 인터페이스와 디자인의 완성도
>
> 프롬프트의 구체성 및 개선 과정의 적절성
>
> 소스 코드와 결과물의 공유 및 제출 자료의 충실성
>
> 5. 유의사항
> 기획서만 제출하는 것이 아니라 Claude Code를 활용하여 실제 작동하는 결과물을 구현해야 한다. 개발 과정에서 사용한 프롬프트는 최초 입력부터 수정 및 개선 과정까지 순서대로 정리하여 제출한다. 결과물의 실행 또는 배포 링크가 정상적으로 작동하는지 확인하고, 소스 코드와 프롬프트를 다른 사람이 확인할 수 있도록 공유한다.
>
> 이 과제 내용에 맞게 결과물 폴더를 만들고 안에 내용을 채우고 구현 ㄱㄱ

이 지시에 따라 `휴먼 컴퓨터` 폴더의 워크북 03, 04, 05, 06을 읽고, 그 프로젝트인 "지금 빈 세탁기"를 구현 대상으로 정했습니다.

## 2. 기획서에서 구현에 적용한 기준

별도의 두 번째 입력은 없었습니다. 1번의 지시가 문서를 보고 구현하라고 했으므로, 아래는 워크북에서 화면 조건으로 가져온 기준입니다.

- 첫 화면에서 바로 가능 대수, 가장 빨리 끝나는 기기, 회수 대기를 함께 보여 갈지 말지를 정하게 한다. (06 To-be 1단계, 요구사항 1)
- 15분 이하면 기다리고, 넘으면 미루기 쉬운 시간으로 안내한다. (05 해석 확인 2)
- 빈 기기에서 종료 알림은 기본 +5분, 정시도 선택 가능, 확정은 버튼 한 번이다. (06 요구사항 2, I03)
- 회수 대기는 이름과 호실 없이 표시하고, 내 세탁을 찾아가지 않으면 회수 알림을 한 번 더 보낸다. (06 요구사항 3)
- 즐겨 찾는 동을 저장한다.
- IoT, 관리자, 고장 신고, 결제, 다국어는 만들지 않는다. 상태는 시뮬레이션으로 둔다. (03 범위)
- 모바일 세로 화면, 한국어, 글자와 배경의 구분이 분명하고 누르는 영역은 크게 한다. (03 디자인 기준)

## 3. 실행하면서 고친 내용

구현한 뒤 브라우저에서 홈, 알림 예약, 회수 대기 상세, 상황 변경, 세탁 시작, 120배속 종료 알림, 회수 알림, 빨래 회수까지 눌러 확인했습니다. 그 과정에서 아래를 고쳤습니다. 사용자가 추가로 친 문장은 아니고, 같은 세션에서 기획과 어긋나거나 조작이 막힌 부분을 수정한 기록입니다.

1. **판단 숫자가 작게 보이던 문제.** "가장 빨리 7분"의 숫자만 12px 회색으로 나왔습니다. 칸 제목용 스타일이 숫자까지 먹고 있었습니다. 제목과 숫자를 분리해 숫자를 22px로 맞췄습니다.
2. **화면이 가운데에서 벗어나던 문제.** 안내 문장의 한 줄 길이가 휴대폰 프레임보다 넓게 계산되어, 넓은 화면에서 프레임이 한쪽으로 밀렸습니다. 프레임 너비를 430px로 고정했습니다.
3. **안내 문장이 버튼에 끼던 문제.** "이 세 숫자만 보고…"와 닫기 버튼이 한 줄에서 겹쳐 읽기 어려웠습니다. 문장 아래로 버튼을 내렸습니다.
4. **설정 아이콘이 장식으로 읽히던 문제.** 톱니 모양 아이콘이 작은 크기에서 해처럼 보였습니다. 조절 막대 아이콘으로 바꿨습니다.
5. **기본 배속이 빨라 7분이 바로 줄어들던 문제.** 처음에는 30배속이라 저녁 혼잡의 "7분"이 십여 초 만에 바뀌었습니다. 기획 화면을 읽을 수 있게 기본을 1배속으로 두고, 발표용 120배속은 설정에 남겼습니다. 처음 화면으로 되돌리기도 1배속으로 맞췄습니다.
6. **120배속에서 버튼이 눌리지 않던 문제.** 다른 기기가 끝날 때마다 설정 화면 전체가 다시 그려져, 배속 버튼을 누르기 전에 화면이 바뀌었습니다. 지금 보고 있는 화면에 영향이 있는 변화만 다시 그리도록 바꿨습니다. 수정 후 120배속에서 종료 알림, 5분 늦은 알림, 10분 뒤 회수 알림, 빨래 회수까지 확인했습니다.

확인된 알림 문장:

- 종료 알림을 예약했어요. 세탁 1, 표준, 종료 5분 뒤
- 세탁이 끝났어요. 종료보다 5분 늦춰 알림. 지금 내려가면 됩니다
- 빨래를 찾아 주세요. 다른 사람에게는 이름 없이 회수 대기로만 보입니다

## 4. 이후에 추가한 프롬프트

### 4-1. 회수와 세탁기 표시 교차 검증

> 지금은 빨래를 찾았다고 하면 끝인데 세탁기랑 교차 검증하고 있는지 확인하고 안돼어 있으면 만들어

확인 결과, 빨래를 찾았다고 누르면 세탁기 상태와 대조하지 않고 바로 빈 기기로 바꾸고 예약을 끝냈습니다. 돌아가는 중인지, 표시가 비어 있는지, 예약한 코스와 같은지는 보지 않았습니다.

수정: **빨래를 찾았어요**를 누르면 내 기록과 세탁기 표시를 나란히 보여 줍니다. 기기가 끝났고 안에 예약한 빨래가 있을 때만 **맞춰 보고 회수 확정**이 나옵니다. 아직 돌아가거나 이미 비어 있거나 코스가 다르면 회수로 끝내지 않습니다. 알림만 끄는 것은 세탁기 표시를 바꾸지 않습니다.
